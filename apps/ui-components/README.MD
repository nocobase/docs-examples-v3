# UI components and interactions

A standalone NocoBase 3 UI example for [UI components and interactions](https://docs.nocobase.com/core/developing-apps/pages-and-interactions/) ([中文](https://docs.nocobase.com/zh-CN/core/developing-apps/pages-and-interactions/)).

The product catalog, review block and stock badges demonstrate application-owned shadcn components, NocoBase UI Library source, action callbacks, route overlays and shared React providers. All products, people and review history are fictional fixtures. Product edits live only in React state until a full reload; review notes reset when leaving that page. No product API, business persistence or approval engine is implemented. The public demo routes require no sign-in and expose no business records. Template authentication and protected administration remain available separately.

## Requirements

- Node.js 24 and pnpm 11 (the package manager version is pinned in `package.json`).
- Generated from `@nocobase/app-template-default@1.0.0-beta.85`, with `@nocobase/app-client@4.0.0-beta.5` resolved in the lockfile.
- Installed `@nocobase/approval-ui` from the NocoBase shadcn Registry; the installed source is committed. Registry provenance is in `docs/registry-sources.json`. This presentational block does not require the approval plugin.
- No external service or API key. SQLite is the verified configuration for the template's own system data; the UI fixtures themselves do not depend on a database dialect. Other database drivers/configurations have not been tested with this example.

## Install and run

From this directory:

```bash
pnpm install --frozen-lockfile
pnpm nocobase config init --dialect sqlite
pnpm nocobase config check
pnpm dev
```

Open the application entry printed after `Local:`, then append `ui-components/catalog` to its base path. For an entry ending in `/main/`, the three demo pages are `/main/ui-components/catalog`, `/main/ui-components/review` and `/main/ui-components/customize`. A direct editor link is `/main/ui-components/catalog/edit/desk-lamp`.

For another machine on your LAN, configure the actual reachable origin before starting:

```bash
pnpm nocobase config set app.publicOrigin=http://<LAN-IP>:13246
APP_SERVER_HOST=0.0.0.0 APP_SERVER_PORT=13246 pnpm dev
```

Use the port printed by the running application. `config.yml`, its generated secrets and `storage/` are local and ignored. The demo does not need the administrator account.

## Checks and screenshots

```bash
pnpm typecheck
pnpm exec vitest run tests/client/ui-components.test.tsx tests/client/client-routes.test.ts tests/client/page-permission-titles.test.ts tests/client/route-overlay.test.tsx tests/project/agents-md.test.ts
pnpm build
```

Start the app first, then run its browser tests. Set `APP_URL` to the actual printed entry, including the deployment base path:

```bash
pnpm exec playwright install chromium
APP_URL=http://<host>:<port>/main/ pnpm exec playwright test tests/playwright/ui-components.test.ts
```

Omitting `APP_URL` skips these browser tests. Set `SCREENSHOT_DIR` to an absolute local directory to capture their states:

```bash
APP_URL=http://<host>:<port>/main/ SCREENSHOT_DIR=/tmp/ui-components-screenshots pnpm exec playwright test tests/playwright/ui-components.test.ts
```

Verification uses the real running NocoBase template and real copied components. It covers filtering, action validation/refusal/retry, pending saves, dirty dismissal, history navigation, browser unload, direct overlay URLs, missing fixture records, query preservation, in-memory reset, stock variants and mobile geometry. Type checking, targeted lint, the component-source checker and the application build are also required. Business persistence, approval execution and business-role authorization are outside this UI example's scope.
