# Walkthrough findings — 2026-10-29

Environment: Node 24.21.0, pnpm 11.7.0, default template 1.0.0-beta.84, SQLite, English UI. Created with `pnpm create @nocobase/app@beta team-tasks --template-tag=beta --json`, initialized configuration, started the clean template, then implemented task management using the prior tutorial source as a reference.

| Observation                                                                                                                         | Resolution                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The documentation pinned beta.81 and a deprecated `app-tutorials` repository.                                                       | Publish this fresh beta.84 application in `docs-examples-v3/apps/team-tasks`; update the agent-first article's source links and screenshots together. Retain the original tutorial for gradual migration. |
| Dev startup selected a free port that differed from `server.port`. A LAN URL must also match the configured public origin.          | Use `APP_SERVER_HOST`/`APP_SERVER_PORT`, verify the printed URL and set `app.publicOrigin` to that origin. Include the full `/main/` path.                                                                |
| The new template protects writes with operation receipts. The old tutorial's bare API snippet omitted the key.                      | Use `useSubmission` and `executeIdempotentMutation`; document the request key, retained input and retry behavior.                                                                                         |
| Initial custom task writes timed out on SQLite because transaction code called user/authorization services on the outer connection. | Resolve authorization before the transaction and bind user administration to its connection. Real CRUD and replay tests pass after the fix.                                                               |
| The user form defaults to Member, while task permissions live in separate roles.                                                    | Explicitly add Task member. Keep generic Member; exclude Task manager and System administrator when verifying member scope.                                                                               |
| English screenshots were paired with Chinese sample values and vague progress instructions.                                         | Use the same English task title, member name and Start/Mark as done menu labels as the actual screenshots, with Chinese explanations in the Chinese article.                                              |
| A username containing hyphens caused the built-in Users endpoint to return 500 `Username is invalid`.                               | Use simple alphanumeric usernames in the walkthrough and test fixtures. This remains an upstream template/plugin issue; the example does not patch dependency files.                                      |
| A React script-tag console error appears on the untouched template home/login pages.                                                | Recorded as a baseline issue, also visible during task checks. Not introduced by the task module.                                                                                                         |

Browser checks cover create/edit/progress/delete, persistence after refresh, search/filter/pagination/sorting, assignees and calendar dates, member/reader/no-access accounts, failed saves, retained drafts, failed refresh after confirmed writes, stale versions, missing records, focus restoration, Chinese IME, 375px layout, both theme presets and light/dark modes. Server/component tests additionally exercise direct unauthorized requests and replayed writes. PostgreSQL/MySQL, deployment, cross-process concurrency, and a full Chinese visual review were not exercised in this walkthrough.

The local demonstration retains Alice and the English tutorial tasks so the screenshots can be reproduced. These are runtime records, not seeds or repository contents. The browser test's separately named accounts are listed in the README.

- Full application suite: 85 files, 513 tests passed. After the final UI review fixes, the affected client/route/locale tests passed again (16 tests).
- Browser suite: 8 scenarios passed, including the added progress preflight failure → retry check. The interactive Alice walkthrough also confirmed the administrator sees the member's completed task after refresh.

Successful creation deliberately returns to the unfiltered first page to show the new task; cancel/detail/edit preserve the prior query.
